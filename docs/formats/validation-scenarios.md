# Сценарии проверки `kozel-game-v1`

Это проверочные сценарии документного контракта для будущего валидатора,
формы ввода и сервера анализа; реализации этих компонентов в репозитории нет.
Проверка JSON Schema выполняется с включённым `date-time`, затем обязательно
проводится воспроизведение по [описанию формата](README.md).
Успех схемы не заменяет воспроизведение.

Исходные документы:

- **C** — [завершённый пример](kozel-game.example.json): три полных раунда,
  `complete`, лимит 101, итог 163:0, победитель «Юг».
- **I** — [незавершённый пример](kozel-game.example_incomplete.json): первые два
  раунда C, `incomplete`, лимит 101, счёт 90:0, корневого `result` нет.

Каждая строка — независимый сценарий. Если не указано иное, меняются только
перечисленные поля. «Принять» означает успех схемы и воспроизведения.
Сервер анализа дополнительно применяет ограничение на завершённость.

## Статус и корневой результат

| № | Вход | Ожидаемый результат |
|---|---|---|
| S1 | C без изменений | Принять; окончательный победитель «Юг» |
| S2 | C без `status` | Принять как `complete`; обратная совместимость |
| S3 | I без изменений | Принять для сохранения и продолжения со следующего раунда; итог партии не назначать |
| S4 | C без корневого `result`, со статусом `complete` либо без `status` | Схема отклоняет оба варианта: обязательный `result` отсутствует |
| S5 | C с корневым `result: null` | Схема отклоняет; `null` не является итогом |
| S6 | I с корневым `result: null`, `{"winner":"Юг"}` либо `{"draw":true}` | Схема отклоняет каждый вариант: поле запрещено целиком |
| S7 | I без `status` | Схема отклоняет: это `complete` без обязательного итога |
| S8 | В C или I `status` равен `""`, `"pending"`, `"Complete"`, `null`, `false`, `0`, `[]` или `{}` | Схема отклоняет каждое значение |
| S9 | C с `result: {"winner":"Север"}` | Схема пропускает структуру; воспроизведение отклоняет неверного победителя |
| S10 | C с `result: {"draw":true}` | Схема отклоняет ничью при `withEggs` |

## Завершённость раундов и партии

Сценарии R1–R8 выполняются независимо для C и I: `incomplete` не ослабляет
контракт раунда.

| № | Вход | Ожидаемый результат |
|---|---|---|
| R1 | У любого раунда удалено одно из `number`, `deal`, `moves`, `result` | Схема отклоняет каждый вариант |
| R2 | Из одной начальной руки удалён камень | Схема отклоняет: требуется семь камней |
| R3 | В первой раздаче у Бориса `0-0` заменён на `0-4` из руки Анны | Схема пропускает; воспроизведение отклоняет: вместо 28 уникальных камней есть дубликат между руками |
| R4 | В первом раунде оставлен только первый ход, прежний результат сохранён | Схема пропускает; воспроизведение отклоняет: ни выхода, ни полной блокировки ещё нет |
| R5 | У первого раунда удалены одновременно конец истории и `result` | Схема отклоняет отсутствие результата; такой частичный раунд сохранить нельзя |
| R6 | В первом раунде `result.eggs` заменён с 62 на 61 | Схема пропускает; воспроизведение отклоняет неверный перенос |
| R7 | Во втором раунде изменён `round_score.Север` или `total_score.Север` с 90 на 89 либо добавлен `fence: {"Север":1}` | Схема пропускает; воспроизведение отклоняет каждое расхождение начислений или забора |
| R8 | Номер второго раунда изменён с 2 на 1 либо 3 | Схема пропускает; воспроизведение отклоняет повтор либо пропуск номера |
| G1 | C либо I с `rounds: []` | Схема отклоняет: нужен минимум один завершённый раунд |
| G2 | I с `status: "complete"` и `result: {"winner":"Юг"}` | Схема пропускает; воспроизведение отклоняет: последний счёт 90:0 ниже 101 |
| G3 | C с `status: "incomplete"` и удалённым корневым `result` | Схема пропускает; воспроизведение отклоняет: третий раунд завершил партию |
| G4 | I с `scoreLimit: 50` | Схема пропускает; воспроизведение отклоняет: второй раунд уже завершил партию |
| G5 | C с `scoreLimit: 50` | Схема пропускает; воспроизведение отклоняет: третий раунд записан после завершения партии вторым |
| G6 | I с `scoreLimit: 50`, `status: "complete"` и `result: {"winner":"Юг"}` | Принять: партия завершена именно вторым, последним раундом |
| G7 | В I оставлен только первый раунд | Принять: завершённая рыба с яйцами 62, запись 0:0, партия продолжается |
| G8 | В I оставлен только второй раунд с номером 1 | Схема пропускает; воспроизведение отклоняет: утрачены первый раунд и перенос 62, начисление 90 не получается из нулевого состояния |
| G9 | К C добавлен ещё один полный раунд с номером 4; проверить с `complete` и с `incomplete` без корневого `result` | Схема пропускает; воспроизведение отклоняет оба варианта: действия после завершения запрещены |

## Заход при записи 0:0

Сценарии Z1–Z4 проверяют выбор следующего захода на рассчитанном состоянии
завершённого кона; для проверки полного документа нужна законная история
выхода или рыбы. Каждый сценарий выполняется при лимитах 50 и 101.
Новая раздача принята, `1-1` принадлежит P1, у P0 есть `0-2`.

| № | Вход | Ожидаемый результат |
|---|---|---|
| Z1 | `withEggs`: P0 вышел, штраф соперника 10 ушёл на забор, обе записи 0 | Следующий `start` — P1 с `1-1`; P0 с `0-2` отклоняется |
| Z2 | `withoutEggs`: P0 вышел, штраф соперника 10 ушёл на забор, обе записи 0 | Следующий `start` — P0 с любым своим камнем, включая `0-2`; P1 с `1-1` отклоняется |
| Z3 | `withoutEggs`: рыбак P0, остатки обеих команд меньше 13, обе записи 0 | Следующий `start` — P0 с любым своим камнем, включая `0-2`; P1 с `1-1` отклоняется |
| Z4 | Первый кон в каждом варианте рыбы | `start` — P1 только с `1-1`; P0 с `0-2` отклоняется |

Отклонённый заход не меняет руки и очередь. Правило `withEggs` при записи 0:0
после рыбы с яйцами также проверяется вторым коном примеров C и I.

## Общие данные, продолжение и приём сервером

| № | Вход или действие | Ожидаемый результат |
|---|---|---|
| D1 | В C и I удалён `playedAt`, переданы дата без времени, время без зоны, `""` либо `null` | Схема с проверкой `date-time` отклоняет каждый вариант |
| D2 | В C и I удалено одно из `teams`, имени/места игрока, `fishVariant`, `scoreLimit` | Схема отклоняет каждый вариант |
| D3 | При продолжении I добавлен третий раунд C, `status` изменён на `complete`, добавлен итог C | Принять; `playedAt`, состав, места, команды, вариант, лимит и первые два раунда сохранены, идентичность партии прежняя |
| D4 | В операции продолжения I изменено время начала, состав игроков, место, команда, вариант или лимит | Отклонить как продолжение той же партии; сравнивать с сохранённым документом, одна схема неизменность не проверяет |
| D5 | Форма получила историю и остатки первого раунда C | Восстановить полную раздачу из 28 камней, проверить раунд; при экспорте не добавлять отдельное поле остатков |
| D6 | В C или I добавлено неизвестное поле `remainders` в корень или раунд | Схема отклоняет; отдельное поле остатков не предусмотрено |
| A1 | Серверу анализа переданы C и затем C без `status` | Принять оба после полной проверки |
| A2 | Серверу анализа передан I | Отклонить с понятной ошибкой о незавершённой партии и необходимости продолжить ввод |
| A3 | I переименован в `game.json` или `game_complete.json` | Содержимое остаётся незавершённым; сохранение допустимо, анализ отклоняется |
| A4 | C переименован в `game_incomplete.json` | Содержимое остаётся завершённым; анализ принимает после полной проверки |
| A5 | Сохранённый I открыт для продолжения | Ввод начинается с раунда 3; первые два раунда и общее состояние сохраняются |

Для обоих вариантов рыбы (`withEggs`, `withoutEggs`) и обоих лимитов (101, 50)
действуют одинаковые ограничения статуса и полноты раундов. При воспроизведении
используются выбранные правила начисления и завершения, включая окончательную
ничью без яиц при равных записях от лимита; забор и неназначенные яйца сами по
себе не завершают партию.
