# Контекст проекта

Всегда отвечай пользователю на русском языке.

## Обязательный старт новой сессии

В начале каждой новой сессии в этом проекте, до первого содержательного ответа
и до выполнения задачи, прочитай с диска этот `AGENTS.md`, затем
[порядок применения правил](.agents/rules/_PRIORITY_RULES.md) и все файлы
`.agents/rules/*.md`. Первое обращение к инструментам посвяти чтению этих правил.
Допустимо предварительное короткое сообщение о начале чтения.

Выполняй это автоматически, без напоминания и запроса разрешения пользователя,
даже если текст `AGENTS.md` уже передан в контексте сессии. Сразу применяй
относящиеся к задаче требования; чтение правил не откладывай до первой правки кода.
Если вывод обрезан, дочитай пропущенные части отдельными вызовами.

Подтверждай чтение только после фактического получения полного текста файлов.
Если файл недоступен, явно сообщи об этом и не утверждай, что он прочитан.
В пределах сессии повторное чтение требуется при изменении правил либо утрате
их содержания из контекста.

## Текущее состояние

Это Flutter-приложение только для веб. Точка входа — [lib/main.dart](lib/main.dart).
Версия приложения, ограничение Dart SDK и подключённые пакеты указаны в
[pubspec.yaml](pubspec.yaml); правила анализатора — в
[analysis_options.yaml](analysis_options.yaml).

Сейчас в проекте стандартное демонстрационное приложение. Не считай
запланированные модули, сервисы или библиотеки уже существующими.

## OpenSpec

Основные спецификации описывают текущее поведение; артефакты активного изменения —
план будущего поведения. Архитектурные решения фиксируй в артефактах изменения.
Перед правкой изучи относящиеся к ней существующие спецификации и код.
Если спецификаций ещё нет, укажи это, не придумывай действующий контракт.

Сначала подготовь и согласуй изменение поведения, затем реализуй его через
падающий тест и проверку результата. Для документационных правок без изменения
поведения приложения отдельное изменение OpenSpec не требуется.
Подробности и завершение работы — в правилах OpenSpec выше.

## Команды разработки

Запускай из корня проекта:

```sh
flutter pub get
flutter analyze
flutter test
flutter run -d chrome
flutter build web
```

Bash-скрипты запускаются в Bash; на Windows можно использовать Git Bash.
Они сами переходят в корень проекта:

```sh
bash tools/tests/run_unit_tests.sh
bash tools/ai/run_openspec_validation.sh
```

Скрипт тестов запускает стандартный набор Flutter, включая widget-тесты;
отдельного набора только unit-тестов пока нет. Установка OpenSpec описана в
[README.md](README.md). Скрипты OpenSpec требуют установленный CLI и ripgrep.
